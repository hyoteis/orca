# Configuration paths and refresh across execution hosts — API audit

**Research date:** 2026-09-07
**Decision ticket:** [Audit configuration paths and refresh across execution hosts](https://github.com/hyoteis/orca/issues/122) (parent: #119)

Scope: what the current tree already offers for (1) choosing an arbitrary host-side `compile_commands.json`, (2) validating and refreshing it, (3) representing host paths, (4) folder-workspace identity, (5) clangd session lifecycle, and (6) the remote-wire safety of each mechanism. Primary sources are the current working tree (commit f667fd977a plus local changes) and [`docs/reference/remote-wire-compatibility.md`](../reference/remote-wire-compatibility.md), whose three rules (optional field safe / new opcode or method must negotiate / published-content changes are stealth wire changes) gate every verdict below.

## Verdict summary

| Capability | Status | Wire safety |
|---|---|---|
| Scope/workspace identity, per-host cache layout | **Reuse as-is** | Desktop IPC + settings only; no wire |
| Setup fingerprint, cache hit/miss, manual reload (`force`) | **Reuse as-is** | Desktop IPC only |
| Host read/stat (`files.read`, `files.stat`, `files.readDir`) | **Reuse as-is** | Shipped RPC methods |
| One-shot directory scan (`files.readDirTree` + fallback) | **Reuse as-is** | `method_not_found` fallback already shipped (f667fd977a) |
| Session restart on config change (single-flight, launch-diff) | **Reuse as-is** | Desktop IPC + renderer |
| Arbitrary-path browse on remote runtimes | **Reuse** `files.browseServerDir` | Shipped; not currently used by the desktop dialog |
| Native file picker (local host) | **Reuse with wiring** (`dialog.showOpenDialog`) | Desktop only; no wire |
| External CDB path in request/scope payloads | **Extend** — new optional fields | Rule 1 safe **only** with capability gating for behavior (see `managed` precedent) |
| Host-side validation of an external CDB | **Extend** — new runtime RPC or host-adapter method | New RPC method → `method_not_found` on old hosts → must ship the readDirTree-style fallback |
| Watching a CDB outside the worktree | **Missing** — `files.watch` is worktree-relative only | New optional param (stripped by old hosts, must degrade) or new method (negotiate) |
| Auto-refresh on CDB change (watcher-driven) | **Missing** — fingerprint re-stat only runs inside setup | Local: new `fs:changed` subscription; SSH: provider watch; runtime: files.watch extension |

## 1. File-selection UX: picking an arbitrary host-side compile database

**What exists.**

- **Local host.** Native pickers behind desktop IPC: `repos:pickFolder`, `repos:pickFolders`, `repos:pickDirectory` all call `dialog.showOpenDialog` ([src/main/ipc/repos.ts:2314-2337](../../src/main/ipc/repos.ts)). They browse the machine the Electron app runs on — correct for `local` execution hosts, wrong for SSH/runtime hosts.
- **Remote runtime hosts.** `files.browseServerDir` is a shipped runtime RPC that lists an **absolute host path** and returns `{ resolvedPath, entries, pathFlavor }` ([src/main/runtime/rpc/methods/files.ts:333-337](../../src/main/runtime/rpc/methods/files.ts), client `browseRuntimeServerDirectory` in [src/renderer/src/runtime/runtime-server-directory-browser.ts](../../src/renderer/src/runtime/runtime-server-directory-browser.ts); consumed by `src/renderer/src/web/web-preload-api.ts`). This is a ready-made remote directory picker primitive for paired runtimes — the desktop C++ dialog simply does not use it today.
- **SSH targets.** No remote picker UI. Browsing goes through the desktop main via `window.api.fs.readDir({ dirPath, connectionId })`, which routes to the SSH filesystem provider (`getSshFilesystemProvider`, [src/main/providers/ssh-filesystem-dispatch.ts:40](../../src/main/providers/ssh-filesystem-dispatch.ts)). The generic remote-path flows (e.g. SSH external terminals) are typed/pasted paths validated by stat, not picked.
- **The C++ setup dialog today.** `useSetupScopeSelection` + `useCodeIntelligenceDirectoryDiscovery` ([src/renderer/src/components/sidebar/code-intelligence-setup-scope-selection.ts](../../src/renderer/src/components/sidebar/code-intelligence-setup-scope-selection.ts), [use-code-intelligence-directory-discovery.ts](../../src/renderer/src/components/sidebar/use-code-intelligence-directory-discovery.ts)) run a one-shot scan from **workspace-relative** starts only — `starts` are filtered by `!isRuntimePathAbsolute(path)` — and present a checkbox tree with `discoverWithin` drill-down. Results come from `readRuntimeDirectory` / `readRuntimeDirectoryTree` with an `expectedExecutionHostId` context that routes local vs SSH correctly. A scan cache persists in `localStorage` (`orca.codeIntelligence.directoryScan.v1`, 10-minute TTL, ≤8 repos, ≤512 KB — [code-intelligence-directory-scan-cache.ts](../../src/renderer/src/lib/language-server/code-intelligence-directory-scan-cache.ts)); prune names shared with the CDB walker live in [src/shared/code-intelligence-directory-scan.ts](../../src/shared/code-intelligence-directory-scan.ts).

**Gap.** There is no way to enter or pick a host-absolute path to an existing `compile_commands.json`, on any host family. Local needs `dialog.showOpenDialog` wiring into the dialog; runtime hosts can reuse `files.browseServerDir`; SSH needs either a typed-path input validated through the provider (stat + read) or a small browse UI over `window.api.fs.readDir` + `connectionId`.

## 2. Host-side read/stat/watch and the fingerprint refresh flow

**Read/stat inventory.**

- Desktop IPC: `window.api.fs.readDir({ dirPath, connectionId })` (local fs or SSH provider), plus local `fs:changed` events (`src/main/ipc/filesystem*.ts`).
- Runtime RPCs ([src/main/runtime/rpc/methods/files.ts](../../src/main/runtime/rpc/methods/files.ts)): `files.read` (:252), `files.readChunk` (:311), `files.readDir` (:322), `files.readDirTree` (:328, new in f667fd977a), `files.browseServerDir` (:334), `files.stat` (:473 — `{ size, isDirectory, mtime }`), `files.watch` (:479) / `files.unwatch` (:495).
- The renderer client is the mixed-version firewall: `readRuntimeDirectoryTree` returns `null` on `RuntimeRpcCallError.code === 'method_not_found'` so callers fall back to the per-directory BFS ([src/renderer/src/runtime/runtime-file-client.ts:487-506](../../src/renderer/src/runtime/runtime-file-client.ts)); `isRuntimeMethodNotSupported` (:452) is the shared predicate, also used for chunked-download degradation (:399, :461). This is the canonical fallback pattern any new file RPC must copy.

**Watching.**

- Local: `fs:changed` IPC from a watcher process (parcel-watcher, with install gating — `src/main/ipc/watcher-removal-gate.ts`, `file-watcher-host`).
- Runtime hosts: `files.watch` is **worktree-scoped** (`params.worktree` selector + relative path); the renderer keeps one shared subscription per (environment, worktree) and fans out (`subscribeRuntimeFileChanges`, `sharedRuntimeFileWatches`, [runtime-file-client.ts:1073-1146](../../src/renderer/src/runtime/runtime-file-client.ts)).
- SSH: the desktop main arms SSH file-explorer watches via `IFilesystemProvider.watch` with **reconnect rearm** (`armSshFileExplorerWatchRearm`, [src/main/runtime/orca-runtime-files.ts:247-330](../../src/main/runtime/orca-runtime-files.ts)); `IFilesystemProvider` includes `watch`, `stat`, `lstat`, `readDir`, `readFile` ([src/main/providers/filesystem-provider-contract.ts](../../src/main/providers/filesystem-provider-contract.ts)).

So every host family can watch — but only **inside a registered worktree**. Nothing can watch an arbitrary host-absolute path today; that is the missing piece for "changed databases auto-refresh" when the CDB lives outside the workspace.

**Fingerprint / refresh (current pipeline).** `runCppSetupPipeline` ([src/main/language-server/code-intelligence-cpp-setup-pipeline.ts:61-178](../../src/main/language-server/code-intelligence-cpp-setup-pipeline.ts)):

1. `host.validateRepoHost(repo)` gates repo→host before anything runs.
2. `setupFingerprint` = `codeIntelligenceSetupFingerprintDigest({ repoId, roots, request, buildInputs })` — sha256 over request options plus per-root mtimes (`CppSetupFingerprintBuildInput`: directory/CMakeLists/gn/.gn mtimes), obtained from `host.statMtimes` ([src/main/language-server/code-intelligence-setup-cache.ts:33-62](../../src/main/language-server/code-intelligence-setup-cache.ts)). The local adapter stats the fs; the SSH adapter batch-stats remotely — the digest core is deliberately host-agnostic.
3. Unless `request.force`, `readCachedCodeIntelligenceSetupResult` reads `setup-manifest.json` from the scope directory and requires: matching fingerprint, `result.ok`, non-empty `clangdExecutable` + `compileCommandsDir`, then re-`access()`es `compile_commands.json` (R_OK) and the clangd binary (X_OK) — so deletion/corruption of the cache degrades to a full re-run, not a stale hit.
4. On miss, tools are discovered/installed, shards generated per build root, merged by `mergeCompilationDatabaseShards` (throws on non-array shards; dedupes by `normalizeRuntimePathForComparison`), and the merged CDB is written atomically (`writeTextFile`: tmp+rename locally, stdin+mv over SSH), then the manifest is cached.

`force` on the request (`CodeIntelligenceCppSetupRequest.force`, [src/shared/code-intelligence-cpp-setup.ts:16-20](../../src/shared/code-intelligence-cpp-setup.ts)) is the manual-reload knob — the dialog re-run sets it because nested CMakeLists edits are invisible to root-manifest mtimes. Drift is only detected **when setup runs**; nothing re-stats build roots or the CDB at session time or on a timer.

## 3. Windows/path handling and the "same execution host" check

- The canonical toolkit is [src/shared/cross-platform-path.ts](../../src/shared/cross-platform-path.ts): `isRuntimePathAbsolute` (flavor-aware), `resolveRuntimePath` (never `node:path.join` across hosts), `normalizeRuntimePathForComparison` (NFC + case + WSL-UNC folding — comparison keys only), `isPathInsideOrEqual` / `relativePathInsideRoot` / `createNormalizedPathInsideOrEqualMatcher` (the ready-made "at least one in-folder command" test), `getRuntimePathBasename`. WSL aliases are folded via `wsl-paths` so `\\wsl$\…` and `/home/…` compare equal where appropriate.
- Remote layouts are always built with `posix.join` regardless of the client platform (`remoteCppScopeDirectoryPath`, [code-intelligence-setup-cache.ts:23-31](../../src/main/language-server/code-intelligence-setup-cache.ts)); remote OS metadata comes from `RemoteHostPlatform { os, pathFlavor, commandDialect, pathSeparator }` ([src/main/ssh/ssh-remote-platform.ts](../../src/main/ssh/ssh-remote-platform.ts)) — `win32-x64` remotes are windows-flavor + PowerShell dialect, and the SSH language-server path already branches on it (`buildWindowsLanguageServerCommand` in [src/main/ssh/ssh-language-server-session-manager.ts:26-31](../../src/main/ssh/ssh-language-server-session-manager.ts)).
- "Same execution host" checks already exist at two layers and a CDB-path check should reuse them: `CppSetupHost.validateRepoHost` (local: `getRepoExecutionHostId(repo) !== 'local'`; SSH: `parseExecutionHostId(...).kind === 'ssh'` + live connection + known platform — [code-intelligence-cpp-setup-local-host.ts:112-115](../../src/main/language-server/code-intelligence-cpp-setup-local-host.ts), [code-intelligence-cpp-setup-ssh-host.ts:84-98](../../src/main/language-server/code-intelligence-cpp-setup-ssh-host.ts)), and `CodeIntelligenceScopeStore.validateWorkspaceBinding` which requires `getRepoExecutionHostId(repo) === scope.executionHostId` and backslash-folded root equality ([code-intelligence-scope-store.ts:236-256](../../src/main/language-server/code-intelligence-scope-store.ts)).

## 4. Folder workspaces vs git worktrees

- Scope identity is `(executionHostId, workspaceKey, language)` where `workspaceKey` is `folder:<repoId>` or `worktree:<repoId>` (`getCodeIntelligenceWorkspaceKey(repo.id, isFolderRepo(repo))`); the store rejects a scope whose kind disagrees with the repo's kind (see `validateWorkspaceBinding` above). Both kinds flow through the identical pipeline — folder workspaces are already first-class.
- Per-host cache locations: local `join(app.getPath('userData'), 'code-intelligence', 'cpp', 'scopes', cppScopeDirectoryName(scopeId))` (sha256 of scopeId, 16 hex chars); SSH `~/.orca/code-intelligence/cpp/scopes/<dirName>` via `remoteCppScopeDirectoryPath`. Orphan sweeps exist on both sides: local `sweepOrphanCppScopeDirectories` at startup; SSH `sweepRemoteOrphanCppScopeDirectories` on transport reconnect ([src/main/ipc/code-intelligence.ts:77-112](../../src/main/ipc/code-intelligence.ts)), with best-effort delete on scope removal (`deleteCppScopeDirectory`, :44-70).

## 5. Session lifecycle: (re)starting clangd on configuration change

- **Single-flight open.** `CppCodeIntelligenceSession.ensureClient` dedupes concurrent opens per `scope.id` via an `opening` promise map; launch is keyed `{executionHostId, scopeId, kind:'clangd', revision}` and the host rejects a duplicate sessionId ([src/renderer/src/lib/language-server/cpp-code-intelligence-session.ts:155-172](../../src/renderer/src/lib/language-server/cpp-code-intelligence-session.ts)).
- **Restart policy.** `CodeIntelligenceScopeStore.upsert` computes `restartRequired` from a **launch-configuration diff** that deliberately excludes `members` but includes `setupStatus.generatedAt` — so member-only edits keep the running clangd alive (it lazily re-reads the atomically rewritten CDB) while a re-run setup restarts it ([code-intelligence-scope-store.ts:36-73, 117-146](../../src/main/language-server/code-intelligence-scope-store.ts)). The client registry broadcasts the drop; cache owners subscribe via `onClientDropped` so stale results are never reused.
- **Deletion/corruption degrade.** `assertClangdCompileCommandsDirExists` runs at session open: local `stat`, SSH `buildRemoteDirectoryExistsCommand` through `SshSetupExecQueue` (a channel that closes without an exit status is treated as a dead transport, not a missing directory) — a missing dir fails **that scope's** session with "Re-run C++ setup" and leaves other mappings untouched ([src/main/language-server/clangd-compile-commands-dir.ts](../../src/main/language-server/clangd-compile-commands-dir.ts), wiring in [src/main/ipc/language-server-sessions.ts:81-88](../../src/main/ipc/language-server-sessions.ts)).
- **Remote runtime hosts.** Sessions go over `languageServer.session` (streaming RPC) and are capability-gated: `language-server.session.v1`, custom-command, and managed-install capabilities from [src/shared/protocol-version.ts:92-102](../../src/shared/protocol-version.ts) are checked in `openRuntimeLanguageServerSession` ([src/renderer/src/runtime/runtime-language-server-session.ts:20-48](../../src/renderer/src/runtime/runtime-language-server-session.ts)). Note its warning: an old host's zod schema **silently strips** unknown optional fields (e.g. `managed`), so new behavior depending on a new field must be capability-gated, not merely field-present.

## 6. Wire-compatibility verdict per mechanism

1. **Desktop-IPC machinery (setupCpp / upsertScope / removeScope / `codeIntelligence:scopeChanged` broadcast, code-intelligence.ts:137-153).** No remote wire involved for local/SSH hosts; safe to extend freely. Caveat: the `scopeChanged` broadcast content is read by renderer code in the same app — but if any of this payload ever rides a runtime stream, Rule 3 applies.
2. **Shipped runtime RPCs reused verbatim (`files.read`, `files.stat`, `files.readDir`, `files.readDirTree`, `files.watch`, `files.browseServerDir`, `languageServer.session`).** Safe: they exist on current released runtimes; the readDirTree path already carries its `method_not_found` fallback.
3. **New optional fields on existing payloads (external CDB path in `CodeIntelligenceCppSetupRequest`, scope payload, or `LanguageServerLaunchRequest`).** Rule 1 safe (zod `.strip()` ignores unknown keys) **as long as no reader requires them** — the `managed`-marker comment in runtime-language-server-session.ts is the in-tree precedent that behavior gates behind a capability, not field presence.
4. **New runtime RPC method (e.g. a host-side "validate external compile database" or "watch arbitrary host path").** Old runtimes answer `method_not_found`; follow the `readRuntimeDirectoryTree` pattern — catch `isRuntimeMethodNotSupported`, degrade (client-side validation via `files.read`, or "host update required" messaging). A new **stream opcode** would additionally need subscribe-handshake negotiation per Rule 2; prefer reusing an existing opcode/event frame with optional fields.
5. **Changing what the host publishes (setupStatus/health content, scope-change projections, watch event content).** Rule 3: identical frames with new meaning break old clients; gate any semantic change behind a runtime capability.

## Conclusion: reuse / extend / missing

- **Reuse as-is:** scope identity + workspace binding, per-host scope cache layout and sweeps, fingerprint digest + manifest cache + `force` re-run, `CppSetupHost` adapter surface (`statMtimes`, `readTextFile`, `writeTextFile`, `validateRepoHost`), session single-flight + launch-diff restart + missing-dir degrade, `cross-platform-path` helpers, `files.read/stat/readDir/readDirTree` with fallback, `files.browseServerDir` (runtime hosts), SSH provider `readDir`/`stat`/`watch` with rearm.
- **Extend (small, wire-safe):** optional external-CDB fields on request/scope/launch payloads with capability gating for any behavior that depends on them; `files.watch` with an optional absolute-path param (old hosts strip it — client must treat "no events" as unsupported and fall back to stat polling); the dialog scan hook to accept host-absolute start paths (drop the `!isRuntimePathAbsolute` filter per host flavor); a CDB validation step built from `readTextFile` + array-shape check + `relativePathInsideRoot` for the in-folder-command rule.
- **Missing entirely:** any UI for choosing a host-absolute `compile_commands.json` (local picker wiring, SSH typed-path/browse, runtime `browseServerDir` integration); host-side validation of a user-supplied CDB (JSON shape, ≥1 in-folder command) — only generated-shard merging validates today; watcher-driven auto-refresh of an external CDB (all existing watches are worktree-scoped); any session-time or periodic fingerprint re-check (drift is only observed when setup runs).
